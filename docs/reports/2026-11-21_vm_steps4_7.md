## 12. Methods facts, read from the code (user questions, 2026-11-22)

Read-only answers; no runs except a one-line shape check of RevIN. Paths under `src/scripts/final/phase1_lib/` are the vendored copies (same line numbers
as their sources). No disagreement between code and docs was found for these six points.

1. **Learned grid resampling.** Each 10 s window (2,500 samples at 250 Hz) is cut out first, then resampled to 100 Hz on its own with
   `scipy.signal.resample_poly(seg, up=100, down=250, axis=1)` (`ltst_pipeline/ml_inference.py:165-184, 110-124`). Anti-aliasing is resample_poly's default
   FIR low-pass (Kaiser window, β 5); no other filter. Each window is filtered alone, so its edges are treated as zeros. The output is exactly 1,000 samples
   (the trim/pad at `:119-123` never acts). The incomplete final window is dropped (`n_segments = n_total // 2500`, `:167, 176`). A window with any
   non-finite value is fed as zeros and its prediction set to NaN (`:180-182, 218`). The repo's training-data builder resamples each segment with the same call
   (`src/scripts/custom_dataset/prepare_regression_datasets.py:142-159`); not verified that this exact builder produced the training H5.
2. **Reference ST label per window.** Value: `.16a` `ee` (µV ÷ 1,000; `Neurokit2_Pipeline/ltst_pipeline/parse_ltst_16a_iso_jp_ee.py:115, 226-227`), defined
   as ST at J+60 minus the isoelectric level, measured on the 16 s average beat (`Tasks/C_neurokit/C_neurokit_baseline.md:272`; `README_phase1_runs.md:62`).
   A beat is assigned by its J+60 sample, not its annotation sample: J+60 = fiducial + JP + 15 samples, fiducial = annotation sample − 16 ms
   (`parse_ltst_16a_iso_jp_ee.py:209`, `compute_locations` `:129-158`); window k holds the beats with J+60 in [start, start + 2,500). Label = median of
   those beats' `ee`, rounded to 4 decimals (`Tasks/phase1/eval/p1_oracle.py:5-8, 50-54`; the trainer's rule, `ltstdb_patient_segment_labeler.py:133, 197-203`).
   Minimum 1 beat, otherwise no label (`p1_oracle.py:54`; labeler `min_beats=1`, `:264-265, 592`); the trainer also drops a window when either lead has
   no beat (`labeler:309`).
3. **Learned-2L normalisation (RevIN, BN).** Per lead, before the leads are joined. The batch arrives as (batch, 2, 1,000) (`src/core/utils/data_utils.py:145`)
   and RevIN runs before patching (`src/core/learner.py:259-260`; `src/patchECG_finetune.py:351`). It transposes to (batch, 1,000, 2) (`src/core/models/layers/revin.py:33`)
   and BN mode takes mean and SD over the batch and the 1,000 samples, separately for each lead (`:46-50`; comment `:11`). The two leads become one 40-patch
   sequence only inside the model (`src/core/models/vit_1d.py:200-202`). Shape check: statistics of shape (2,). The statistics depend on the batch, also
   at evaluation: training used batches of 128 windows; step-6 inference used 1,024 consecutive windows of one record (`ml_inference.py:103, 203`;
   `fin_step6_infer.py:89`).
4. **Patch normalisation.** Confirmed: the patch embedding is `LayerNorm(50) → Linear(50 → 128) → LayerNorm(128)` (`src/core/models/vit_1d.py:121-125`),
   applied to every patch in the joined-leads path (`:202`) and the per-lead path (`:218`). Each 50-sample patch is normalised to its own mean and SD
   before projection, so the patch's offset and scale are removed at this step.
5. **Pre-training loss** (fixed code, `src/core/support/patch_mask.py:66-74`, commit b8f688d):
   L = Σ_{b,v,p} m_{bvp} · (1/50) Σ_{s=1..50} (ŷ_{bvps} − y_{bvps})² / Σ_{b,v,p} m_{bvp}, with m = 1 for a masked patch (`_inverted_mask`; the mask
   array marks kept patches with 1, `:58-59, 169-192`). The squared error is averaged over the 50 samples of each patch (`:72`) and the total is divided
   by the number of masked patches in the whole batch, over all windows and leads (`:73`). Mask ratio 0.4: 12 of 20 patches per lead kept, 8 masked (`:173`).
   Target: the patched target tensor passed in (`:51-52`).
6. **SQI** (`ltst_pipeline/old_fsm_gs.py:376-440`). Yes, the 25th percentile of the per-beat SNR: beat = R ± 0.35 s (88 samples each side, 177 in all);
   template = mean beat; P_sig = mean(template²); P_noise per beat = mean((beat − template)²); SNR = 10·log10(P_sig / P_noise); SQI = 25th percentile
   (`:397-399, 422-440`). High-pass: Butterworth, order 3, 0.67 Hz, zero-phase (`filtfilt`) (`ltst_pipeline/filters.py:7-14`), applied to the whole
   artifact record before any window is taken (`fin_step5_nk.py:167`). Partial beats are discarded: only R-peaks at or before the anchor whose whole
   segment lies inside the 30 s window, which ends 0.35 s after the anchor, are used (`:402-403, 408-418`); fewer than 3 beats, or a window reaching
   outside the record, gives NaN (`:405-406, 419-420`).

## 13. Methods facts, read from the code: detector choice, Fiducial-FP, gate, Learned-2L head (user questions, 2026-11-22)

Read-only answers (one shape check of the model); paths under `src/scripts/final/` (vendored copies keep their source line numbers).

**A. R-peak detector choice**
1. **Candidates.** The freeze rule compared neurokit, rodrigues2021 and khamis2016 (`phase1_lib/c20_finalists.py:52`; `README_phase1_runs.md:131-136`).
   They were the finalists of a screen of 16 detectors on the noisy signal (C §10c: christov2004, elgendi2010, engzeemod2012, gamboa2008, hamilton2002,
   kalidas2017, khamis2016, manikandan2012, martinez2004, nabian2018, neurokit, neurokit_cleaned, pantompkins1985, promac, rodrigues2021, zong2003; recorded
   only as the peak folders `DATASET NK/C_neurokit/c14_detectors`, `c16_all_detectors`). khamis2016 reached the final on its alarm estimate rather than on
   detection in noise (`Tasks/C_neurokit/C_neurokit_baseline.md:1152`). An explicit rule for picking the finalists: not recorded.
2. **Records and signals.** Clean DMY beats of the 15 scored records (s20121 computed but filtered out, `phase1_lib/c21b_step4_report.py:204`; `c20_finalists.py:56-57`),
   each detector with its own fold offset fitted on the training records of the record's fold (`c21b:135`; `c20_finalists.py:9-11`), with and without masked
   pairs (`c21b:249`); both gave rodrigues2021 outright, so the tie-break was not needed (`DATASET NK/C_neurokit/c21_step4/report/rule.txt`). Artifact seeds 42 and
   43 enter only through the tie-break (`c21b:146-153`). The per-fold variant was reported, not used (`c21b:263-267`). The DMY value in this rule is the
   5-sample mean at the delineated J+60 minus the 5-sample mean at R − offset, median over each DMY beat's NL/NR beats (`c21b:50-63`; `c20_finalists.py:4`),
   not Fiducial-FP. Decision recorded 2026-11-19 (`docs/DECISIONS.md:4`); the phase-1 step-4 run that made it is older (date not confirmed from the files).
3. **Rule as implemented** (`c21b:222-245`). Per lead (II, V2), three clean DMY metrics, unordered: MAE, p100 (% |error| > 0.1 mV), worst record-lead MAE;
   margins 0.005 mV (both MAEs) and 1 point (p100) (`c21b:46`). A beats B if A is better beyond the margin on at least one metric-lead and worse beyond the
   margin on none. The detectors no other detector beats are kept; one left = chosen; several = lowest spurious-R-peak rate inside noise bursts (detected
   peak > 148 ms from any `.atr` beat), pooled over seeds 42 and 43, s20121 and masked pairs out (`c21b:241-244, 153, 251`). Code vs docs: the docstring
   (`c21b:9`) names only MAE and p100 in the tie; the code also uses worst record-lead MAE, as the README does (`README_phase1_runs.md:146`). The docstring
   notes the margin was set after §12 had been seen.

**B. Fiducial-FP (NK-FP) as used for the final tables**
1. **Expert points.** `.16a` annotation (symbol `s`), aux "[DMY]ST<lead> aa…hh, ISO, JP, J80/60, NL, NR": `ISO_ms` and `JP_ms` are the 9th and 10th integers
   (`ltst_pipeline/parse_ltst_16a_iso_jp_ee.py:76-86, 115-127`; `c4_dmy_vs_nk.py:38-47`). Fiducial = annotation sample − 4 samples (16 ms) (`c4_dmy_vs_nk.py:34`);
   isoelectric point = fiducial − ISO_ms; J point = fiducial + JP_ms (`fin_step5_nk.py:99-101`); the convention ("annotation = fiducial + 16 ms; ISO before,
   JP after", `parse_ltst_16a_iso_jp_ee.py:129-142`) is used without rounding to samples and without its sign fallbacks (algebraically the same for positive values).
2. **Matching.** Nearest rodrigues2021 R-peak on the baseline signal of the same lead (step-4 cache; `fin_step5_nk.py:70-72, 95-97`), |R − annotation sample|
   ≤ 25 samples (100 ms) (`c4_dmy_vs_nk.py:33`); beats with no match are dropped from the fit (`fin_step5_nk.py:98, 102`).
3. **a and b.** Per beat a = R − iso, b = J − R (ms) (`fin_step5_nk.py:100-101`); fitted value = plain median over all matched DMY beats pooled across the
   fold's 13 non-test records, masked pairs excluded, per fold and lead (`:63, 123-127`); samples = round(ms / 4) (`c5_iso_offsets.py:34-35`). All fitted
   medians were multiples of 4 ms (`runs/step5/nkfp_ab.csv`), so no rounding occurred.
4. **Levels.** 5-sample means (half-width 2, ±8 ms at 250 Hz; `c5_iso_offsets.py:38-46`): baseline centred at R − a, ST centred at R + b + 15 samples (60 ms)
   (`fin_step5_nk.py:145-148`); deviation = ST − baseline, rounded to 6 decimals (`:149`); unfiltered 250 Hz signal of that condition (`:159, 166`) with that
   condition's cached peaks (`:181`).
5. **Usable beats and windows.** Usable = both 5-sample windows inside the signal, so both values finite (`c5_iso_offsets.py:41-45`; `c13_fp_gap.py:62`).
   Each beat goes to the 10 s window that holds its ST point (R + b + 60 ms) on the grid [2500k, 2500k + 2500) (`c13_fp_gap.py:54-57, 63`; the last window
   has no upper bound). Value = median of ≥ 5 usable beats, else none (`c13_fp_gap.py:41, 68-71`).

**C. Smaller points**
1. **Gating per window.** The FSM evaluates the SQI at each window's anchor (2500k + 2499 Learned, 2500k + 2500 Fiducial; `ltst_pipeline/old_fsm_gs.py:487-514, 522`).
   It rechecks only after ≥ 5 s and windows are 10 s apart, so every window gets a fresh SQI at its own anchor; the 5 s cadence never acts. Good = finite
   and ≥ 6 dB; otherwise that window causes no state change and adds no time to any timer (`:513, 535-700`; `prev = samp` at `:701`). In the final pipeline
   the SQI per anchor is precomputed and passed to the same call through a lookup (`fin_step7_tier1.py:58, 68-77`; values `fin_step5_nk.py:167, 181, 198-201`).
2. **Learned-2L head.** One model, one CLS token, two outputs. Without augmentation, fine-tuning builds a single-channel ViT whose input is both leads as one
   2,000-sample series (40 patches of 50) (`src/patchECG_finetune.py:272-273`; `src/core/utils/data_utils.py:145`), with one CLS token prepended
   (`src/core/models/vit_1d.py:200-215`). Head: LayerNorm(128) → Linear(128 → 2) on the CLS output (`vit_1d.py:76-87`); 2 outputs from the dataset's lead
   selection (`src/core/datasets/ecg_dataset.py:139-142`), in target order II, V2. Inference builds the same model (`ml_inference.py`, `ViT(..., channels=1,
   num_classes=2)`). The per-lead path with one CLS token per lead (`vit_1d.py:217-235`) is used only with `per_lead_aug`, not in the final runs.
3. **`context_points` = 5000.** A command-line argument ("sequence length", default 5000; `src/patchECG_finetune.py:81`, `src/patchECG_pretrain.py:44`) that
   nothing in `src/` reads. The input length is taken from the data, leads × samples per lead = 1 × 1,000 or 2 × 1,000 (`data_utils.py:145`;
   `patchECG_finetune.py:272`, `patchECG_pretrain.py:207`). The hyperparameter table's "context points 5000" row has no effect and should be dropped or
   footnoted as unused.

## 15. Methods facts: scoring, training grid, noise, gold standard, training seed, bootstrap, folds (user questions, 2026-11-23)

Read-only: no code changes and no pipeline reruns. Small checks were run from scratch scripts (repo `.venv`), which are not in the repo. Paths under
`src/scripts/final/phase1_lib/` are the vendored copies, which keep their source line numbers. Each item says whether the answer comes from
reading the code or from a check.

1. **T5 scoring, "union of II and V2 alarms, FULL scope".** *Code, plus checks.*
   - **What "union" means.** Both leads' alarms go into one list, with masked pairs removed (`fin_step7_tier1.py:80-83`, `nk_core.apply_mask`
     `:86-93`). They are scored against the gold-standard (GS) episodes of both leads. An alarm can only match an episode of the same record and
     the same lead (`nk_core.py:142`). So it is each lead's alarms against that lead's GS episodes, with the counts added. It is not a union of
     alarm intervals across leads.
   - **Can it differ from the per-lead sum?** No. Because matching never crosses leads, TP, FP, FN and Ignored are exactly own-II + own-V2,
     and so are the time components (see the duration bullet). *Check:* all 42 step-7 alarm files (every pipeline, seed and condition): FULL
     equals own_II + own_V2 for TP/FP/FN/Ignored and tTP/tFP/tFN/tTN, 42 of 42.
   - **How a match is counted** (`nk_core.match_episodes`, `:123-190`, a port of `evaluation.py`). Any overlap > 0 s counts (`:152`).
     - A GS episode hit by at least one alarm is one TP (`:181`). Extra alarms on an already-hit episode are "Ignored" (redundant), not FP
       (`:176`).
     - An alarm is FP only if it overlaps no episode (`:182`).
     - One alarm that overlaps two episodes is credited to both, so it gives 2 TP. Precision = TP/(TP + FP) therefore mixes episode counts (TP)
       with alarm counts (FP).
   - **How often one alarm gets several TPs** (*check*, gated). It happens in every run:
     - Fiducial-FP: 10 of its 67 credited alarms account for 27 of its 84 TP.
     - L2 S1: 10 alarms, 31 of 75 TP.
     - Fiducial-PR: 10 alarms, 36 of 66 TP.
     - Alarm-level precision (alarms overlapping any episode ÷ all alarms) compared with the T5 precision: Fiducial-FP 0.924 vs 0.933, L2 S1
       0.750 vs 0.773, Fiducial-PR 0.687 vs 0.759, L1 S1 0.688 vs 0.729.
   - **FULL scope** means both leads, the 15 test records, s20121 removed (`load_gs`, `nk_core.py:56-62`) and the 6 masked record-leads removed
     (`MANUAL_OMIT`, `:45-52`). The other scopes, `own_II` and `own_V2`, keep one lead (`scope_filter` `:96-104`, `gs_scope`
     `score_alarms.py:104-105`). GS: 101 episodes on the 15 records (II 69, V2 32), none on a masked pair (*check*).
   - **Duration metrics** (`nk_core.score_time`, `:236-278`). Alarm and GS intervals are merged within each record and lead (`intervals_by_group`
     `:225-233`, `merge_intervals` `:194-205`), never across leads. TP/FP/FN/TN time is computed per record-lead and then summed. TN is the
     record duration minus the union of alarm and GS time (`:256`), over the unmasked record-leads (`universe_pairs` `:289-293`).
   - **Suggested thesis wording:** "alarms of both leads, each scored against the GS episodes of its own lead, counts pooled".

2. **Training grid vs evaluation grid: confirmed.** *Check.*
   - **Training windows** start at a record-specific offset: the first J+60 sample of the record, the earliest over both leads' `.16a` beats
     (`ltstdb_patient_segment_labeler.py:167-175`, default `--start_mode first_j60` `:595`).
   - **Evaluation grids** start at sample 0 in steps of 2,500: the learned grid (`ml_inference.py:167, 176`), the labels and the Fiducial grid
     (§14.4). *Check:* every window start is a multiple of 2,500 and the first is 0 for every record.

     equals the first J+60 sample for all 15 test records. For s20121, which is not in that file, the first J+60 is sample 25,559, and its
     stored segment 0 equals raw[25,559 : 28,059] exactly.

     windows are shifted by 0.9–8.6 s against the evaluation windows.

3. **Noise (`ltst_pipeline/noise.py`, identical to the Neurokit2_Pipeline source).** *Code, plus a check with the local `em`.*
   - **Resampling.** NSTDB `em` (360 Hz, 650,000 samples, 2 channels, mV) is resampled once, whole, to 250 Hz with `resample_poly(up=25,
     down=36)` (`:79-81`). It is added at its recorded amplitude, with no SNR scaling (`:113-115`). RMS inside bursts: about 0.75 mV on lead II
     and 0.20 mV on V2.
   - **Lead mapping.** `em` channel 1 (`noise1`) goes to signal column 0 = lead II, and channel 2 (`noise2`) to column 1 = V2 (`:113-115`).
   - **Burst lengths:** 60, 120 or 240 s, each equally likely (`:88, 96`).
   - **Gaps:** the gap from the end of one burst to the start of the next is drawn from N(15, 5) min and clipped at 0 (`:89-91, 126-130`).
     It is not measured onset to onset.
   - **The first 10 min are not left clean.** The first burst starts at sample 0 (`:86, 101`), so the record starts contaminated: 0–60 s for
     seed 42, 0–120 s for 43, 0–240 s for 44. A burst that would run past the record end is not added (`:98-99`).
   - **Shared bursts.** Both leads share the burst times and the same `em` excerpt (one `start_idx` per burst, `:107-108`), but each lead gets
     its own `em` channel.
   - **What the seed controls.** A NumPy `default_rng(seed)` (`:70`) draws, per burst: its length, the start of its `em` excerpt, and the next
     gap. The draws depend only on the seed. *Check:* for each seed, the shortest and longest test records get the same burst times and the
     same noise samples. The rest of the longest record continues the same sequence.
   - **Per seed** (longest record): 83, 81 and 79 bursts; 13.6–14.2 % of the record contaminated; gaps 1.2–29.6 min.

5. **Training seed.** *Code.* `--seed` (S1 = 200 + fold − 1, and so on) calls `random.seed`, `np.random.seed`, `torch.manual_seed` and
   `torch.cuda.manual_seed_all` before anything else runs (`src/patchECG_finetune.py:259-264, 492`). It therefore fixes:
   - **Initialisation:** `get_model` runs `init_weights` (Xavier-uniform on every Linear) after the seed is set (`learner_utils.py:19-21, 50`).
     For pre-trained runs, `transfer_weights` then overwrites every matched backbone layer, but not the head (`:183-203`, `exclude_head=True`).
     So the seed sets the regression head (and any unmatched layer) in pre-trained runs, and all weights in no-PT runs.
   - **Data order:** the training loader shuffles (`shuffle_train=True` default, `data_module.py:16`; `DataLoader(shuffle=...)` `:63-69`) with
     torch's global generator, so the batch order follows the seed.
   - **Nothing else:** dropout = 0, head dropout = 0, augmentation none and LoRA off (run `params.txt`).
   - **Not deterministic:** cuDNN determinism is not set (no `cudnn`/`use_deterministic_algorithms` call in `src/`). Runs with the same seed are

     only reshuffles when that column is missing).

6. **T7 bootstrap.** *Code* (`fin_step7_tier1.py:216-254`; 5,000 resamples, seed 20,260,805, `:49`).
   - **Resampling.** Each resample draws the 15 test records with replacement (`:218`). The same draw is used for both pipelines (paired,
     clustered by record).
   - **dF1.** Per training seed, the per-record TP/FP/FN (both leads, FULL scope) are summed over the drawn records, and F1 =
     2TP/(2TP + FP + FN) is recomputed from those pooled counts (`:225-226, 232-233`). The three seeds' F1 are then averaged (Fiducial: one
     value).
   - **dFP** is the same with the FP sum. **dMAE** resamples each lead's unmasked records and recomputes MAE as Σ|e| / n over the drawn
     records' windows, so windows are weighted, not records (`:239-250`).
   - **CI:** percentile, the 2.5th and 97.5th percentiles of the resampled differences (`np.nanpercentile`, `:236, 250`). The reported delta is
     the full-sample value, not the bootstrap mean.

## 17. Do all methods give the FSM the same windows? (user questions, 2026-11-23)

Read-only: code reading, plus one check that reran only the Fiducial FSMs (scratch script, nothing written to the repo or the run folders).

1. **Why Fiducial has a tail window and Learned does not.** *Code, plus a check.*
   - The learned grid comes from the signal length: `n_segments = n_total // 2500` (`ltst_pipeline/ml_inference.py:167`). The models need
     exactly 2,500 samples (1,000 at 100 Hz), so the incomplete tail is dropped.
   - The Fiducial grid is the stored phase-1 grid (`c13_fp_gap.grid`), built by `Neurokit2_Pipeline/ltst_pipeline/segment_aggregation.py`.
     It adds windows `while segment_start <= max_sample`, with `max_sample` = the last beat's J+60 (`:108, 124`). It never reads the record
     length. The grid therefore ends at the window holding the last beat: one extra full-length window that runs past the record end when that
     beat lies in the incomplete tail, none otherwise. This is a side effect of the code, not a design choice.
   - Check: in all 32 record-leads the stored grid starts at 0 and has exactly (last J+60) // 2,500 + 1 rows. This explains the exceptions
     in §14. For example, s20051 II's last J+60 (19,179,634) lies before its tail (from 19,180,000), so its grid ends at the last complete
     window. s20051 V2's last beat (19,180,921) lies in the tail, so V2 gets the extra window.

2. **What each method gives the FSM.** *Code.* Both use the grid [2,500k, 2,500k + 2,500) from sample 0. Both feed every window
   k = 0 … N//2,500 − 1, one per window, in order, through the same `old_fsm_gs.run_fsm_on_record` and the same scorer. Windows without a value are
   passed as NaN, not left out. There are three differences:
   - **Timestamp.** Learned: 2,500k + 2,499, the window's last sample (`fin_step6_infer.py:80`). Fiducial: 2,500k + 2,500
     (`fin_step5_nk.py:194`). They are 1 sample (4 ms) apart, inherited from each method's phase-1 convention. Under the gate, the SQI is computed
     at each method's own timestamp.
   - **Tail window.** Fiducial only, in 19 of 26 scored record-leads (§14). It changes no TP, FP, FN or F1.
   - **Missing values.** Learned: 0 NaN windows (§14). Fiducial-FP: about 0 (§4). Fiducial-PR: about 17–25 % (§11). On a NaN window the FSM
     sets `prev = samp` and changes neither state nor timers (`old_fsm_gs.py:526-532`). Warm-up timers add only `samp − prev` (e.g. `:552, 575`).
     A NaN gap therefore pauses a warm-up without resetting it, and the gap's time does not count toward the 10 min. This difference is
     Fiducial-PR's own failure to measure those windows, and the alarms it misses because of it count against it.

3. **Check: Fiducial FSMs on the learned timestamps.** *Check.* Fiducial-PR and Fiducial-FP were rerun with timestamp 2,500k + 2,499 in 14 runs:
   clean, plus artifact and gated for seeds 42, 43 and 44. Each was tested with the learned SQI (computed at 2,500k + 2,499) and with Fiducial's

   | gated 43 / 44 | 69/21/32, 70/21/31 → same | 85/8/16, 83/7/18 → same |

4. **Verdict.** For the alarm tables (T5, T6, T7 alarm parts) all methods are run the same way: same windows, same order, same FSM, same scorer.
